# 0. РЕЗЮМЕ

Хост-мод **уже есть**. В нём есть мир, геометрия, «глаз» в небе, парящие блоки — но **нет ни одного эффекта**: нет тумана, нет объёмного света, нет отражений, нет пара. Картинка «плоская».

Это ТЗ описывает **`volfx`** — слой атмосферных эффектов, который:

1. **навешивается на существующий мод** через узкий API — **3 обязательных вызова + 7 опциональных** (§13.2). При отсутствии модуля хост работает ровно как раньше (`NoopVolFx`);
2. воспроизводит **ровно ту картинку, что на референсах** — с измеримыми допусками (§2), а не «похоже»;
3. строится вокруг **одной центральной технологии — фроксельного объёмного тумана** (froxel volumetric fog): одна система даёт туман, высоту, лучи света, свечение точечных источников, корректный порядок с прозрачностью и автоматически верный туман для отражений и частиц;
4. работает **на OpenGL 3.2 Core без compute** и **без правки ванильных core-шейдеров**;
5. укладывается в бюджет **≤ 4.7 мс** GPU и **≤ 1.0 мс** CPU на 1080p на среднем GPU (§15.1), с автоматической деградацией качества;

**Главный физический вывод из референсов (§2.1):** то, что мы видим на этих скриншотах — **это не «скайбокс + туман по цвету»**. Небо на 80% состоит из **рассеянного света тумана** (in-scattering). Градиент неба — это интеграл по оптической толще тумана вдоль луча. Именно поэтому картинка выглядит «дорого»: она физически согласована. Любая реализация, где небо — текстура, а туман — `mix(color, fogColor, factor)`, **не даст этого вида никогда**. Это зафиксировано как обязательное архитектурное требование.

## 1.2. Что вне границ

- **Не переписываем хост-мод.** Никаких «предлагается отрефакторить мир». Только аддитивные хуки.
- **Не делаем PBR-рендер блоков** — это не задача слоя эффектов.
- **Не делаем глобальный GI/RT.** Тени в тумане — аппроксимация (§6.5), и это честно указано.
- **Не трогаем ванильные core-шейдеры** (вариант B в §5.7 — только как опциональная ветка с предупреждением о совместимости).
- **Не поддерживаем Optifine/Iris/Oculus.** Они полностью подменяют рендер-конвейер
  и делают любой объёмный эффект непредсказуемым. Детект при старте → предупреждение в лог.
- Сетевой код, геймплей, генерация мира — вне границ.

## 1.3. Почему модуль, а не мод

Хост-мод уже существует и работает. Значит:

- `volfx` подключается как **опциональная зависимость**: `optional` в `mods.toml`, мягкая проверка `ModList.get().isLoaded("volfx")`.
- Публичный интерфейс — `IVolFx`, **с реализацией `NoopVolFx` по умолчанию**: хост-мод линкуется и работает без модуля, все вызовы молча ничего не делают.
- **Профили данных в JSON/TOML** — 90% настройки эффектов делается без единой строки Java, из ресурспака/датапака.

## 1.4. Контракт минимальной интеграции

Хост-мод обязан сделать ровно это (и ничего больше):

```java
// 1) при инициализации клиента
VolFx.init(new VolFxConfig());

// 2) раз в клиентский тик
VolFx.tick(clientLevel, cameraEntity);

// 3) объявить зону тумана (1 раз на измерение, при загрузке)
VolFx.setAtmosphere(level.dimension(), AtmosphereProfile.byName("mirror_world"));

// 4) зарегистрировать плоскости-зеркала (вода/пол)
VolFx.registerMirror(new MirrorPlane(y, 0.02f /*roughness*/, true /*enableSSR*/));

// 5) зарегистрировать источники света (фонари, эмиссивные блоки)
VolFx.addLight(new PointLight(pos, color, intensity, radius, volumetric));

// 6) зарегистрировать эмиттеры пара
VolFx.addSteamEmitter(new SteamEmitter(pos, params));

// 7) собственный мир без неба — передать флаг
VolFx.setSkyOverride(level.dimension(), SkyProfile.byName("eye_void"));
```

Всё остальное модуль делает сам, через свои `RenderLevelStageEvent`-хуки. **Ни одна строка хост-мода не должна знать о шейдерах, FBO и фрокселях.**

# 2. АРТ-ДИРЕКШН ПО РЕФЕРЕНСАМ (ИЗМЕРЕННЫЕ ЧИСЛА)

> Все значения ниже получены **прямым измерением** ваших скриншотов (скрипт: медианное квантование палитры, пополосные средние, профиль яркости по 20 срезам, статистика насыщенности, локальный градиент). Это не «видение художника», это целевые числа для приёмки.

## 2.1. Разбор: почему эти кадры выглядят так, как выглядят

### 2.1.1. Небо — это туман, а не скайбокс

Вертикальный профиль **яркости** (20 срезов сверху вниз), `world4_mirror`:

```
140  153  172  190  184  188  196  182  196  217  211  175  155  124  102  91  68  49  36  24
 ↑верх кадра                                                    ↑горизонт        ↑зеркальный пол
```

Небо **светлеет вниз**, к горизонту, и достигает максимума **ровно на линии горизонта** (217). Это подпись **однократного рассеяния в тумане**: луч, идущий к горизонту, проходит через толщу тумана в разы длиннее, чем луч, идущий в зенит. Яркость неба — это не цвет текстуры, это интеграл:

```
L_sky(dir) = ∫_0^∞ T(t)·σ_s(t)·p(θ)·L_sun dt  +  L_ambient·(1 - T)
```

**Требование:** высотный градиент неба обязан **возникать автоматически** из модели тумана. Отдельная градиентная текстура неба как *основной* механизм **запрещена** (допускается как слабая добавка для артистических зон).

### 2.1.2. «Море тумана» снизу

`loc12_void`, профиль яркости:

```
194 202 202 201 200 201 207 220 210 198 189 162 162 159 143 102 94 93 89 88
 ↑ небо, ровное ~200                          ↑ тело туманного моря ~145   ↑ дно/тень
```

Полоса 162→143 — это **верхняя поверхность туманного моря**, затем она темнеет вниз (94→88). Физически верно: туман **подсвечен сверху**, а в глубине он в тени и слабее рассеивает. **Требование:** туман обязан быть **освещён по высоте**, а не иметь один цвет. Плоский цвет тумана = брак.

Отношение «море/небо» по яркости: **0.89**.

### 2.1.3. Потеря горизонта

В обоих референсах **горизонта нет вообще** — дальние объекты исчезают в белизне до того, как станут мелкими. Это означает:

```
σ_t ≥ 0.014 м⁻¹   →   оптическая толща 3 достигается на ≈ 210 м
σ_t ≈ 0.019 м⁻¹   →   «стена» на ≈ 160 м
```

**Требование:** дальний хвост тумана обязан **насыщаться** (`T → 0`), а не «выходить на плато». Любая реализация, где туман обрезается за `renderDistance`, даёт видимую полосу — брак.

### 2.1.4. Тёплая палитра, холодные тени

Везде R > G > B в светах, и R < G < B в тенях:

| | R : G : B (норм. к R) |
|---|---|
| Туман / небо (`#E9E5D9`) | **1.000 : 0.983 : 0.931** |
| Тёмные структуры (`#15191B`) | **1.000 : 1.190 : 1.286** |

**Требование к грейдингу (§11.3):** split-toning — света в тёплый «ivory», тени в едва заметный холодный. Это то, что делает картинку «дорогой». Стандартный серый туман (`#808080`) даст пластмассовость.

### 2.1.5. Почти монохром

Средняя насыщенность: **0.114** (`world4_mirror`) и **0.102** (`loc12_void`). Мир практически **чёрно-белый с редкими красными акцентами**.

Средний локальный градиент: **2.2–2.6 / 255** (для сравнения, обычная игровая сцена — 10–25). Изображение **на 90% состоит из гладких градиентов**.

> **Отсюда два инженерных вывода, которые нельзя игнорировать:**
> 1. **Дизеринг против бандинга — критичен.** Гладкие градиенты на 8-битном выходе дадут видимые полосы. Обязателен (§11.5).
> 2. **Тени и контуры — единственный источник «читаемости».** При таком низком контрасте вся композиция держится на 15% тёмных силуэтов (`#15191B`, `#2C2D2E`, `#3D3D3C` — суммарно ~37% пикселей палитры). Значит: **эффекты не должны «съедать» силуэты**. Плотность тумана на дистанции силуэта обязана сохранять контраст ≥ 0.75 от контраста без тумана (проверяется гейтом).

### 2.1.6. Акценты — только красный

Единственный цветной элемент — **красные фонари**: ядро свечения доходит до `#B96B6D` (184, 107, 109) в `world4_mirror` и `#984A4A` (152, 73, 74) в `loc12_void`, вокруг — мягкий ореол в тумане, средний тон `#5B181B`.

**Требование:** красный присутствует **≤ 0.3% пикселей**. Это не «красные лампочки» — это **свечение в объёмном тумане** (см. §6.2). Ореол вокруг фонаря на 3–6 блоков обязан быть виден именно как рассеяние, а не как спрайт.

### 2.1.7. «Глаз»

Присутствует в обоих кадрах. В `loc12_void` измерено: **глаз ярче окружающего неба на +34 ед. яркости** (218.8 против 184.4, относительный контраст 1.19). В `world4_mirror` ядро глаза — `#DFDACD` (223, 218, 205), это самый яркий участок неба.

**Требование:** «глаз» — **отдельный слой неба, видимый СКВОЗЬ туман** (§10). Он не должен «приклеиваться» к экрану и не должен обрезаться туманом. Контраст глаза должен управляться дистанцией/высотой — при погружении в туман он гаснет первым.

## 2.4. Восемь железных правил арт-дирекшна

7. **Силуэты не съедаются туманом.**
8. **Никаких жёстких границ** ни по расстоянию, ни по высоте, ни по LOD. Только плавные переходы.

## 3.2. Почему туман применяется в P10, а не в P4

Прозрачные объекты (пар, вода, стекло) **находятся внутри** объёма тумана. Если применить туман постпассом поверх финального блендинга — прозрачность окажется «поверх» тумана, что мгновенно ломает картинку (пар будет выглядеть «наклеенным»).

**Решение (обязательное):**

```
1) Туман применяется в P10 как композит к НЕПРОЗРАЧНОМУ буферу + небу
   → учитывает только путь камера→первая непрозрачная поверхность

2) Каждый прозрачный фрагмент (вода, пар, стекло) САМ применяет к себе туман:
   в его шейдере берётся интеграл тумана по отрезку [камера → фрагмент]
   из тех же фрокселей (4–6 сэмплов) и применяется ДО блендинга.

   color_final = color_объект · T(камера→объект) + L_inscatter(камера→объект)
   затем стандартный alpha-blending поверх уже затуманенного фона.
```

Это даёт **правильный порядок без сортировки** и без OIT. **Упрощение для Tier C:** один сэмпл фрокселя в точке фрагмента, `T = exp(-σ·d)`. Разница видна только в очень плотном тумане.

# 4. АТМОСФЕРА И НЕБО

## 4.1. Модель

Небо не рисуется текстурами, а **собирается из трёх компонент**:

```
L_sky(dir) = L_atmosphere(dir)          — рэлеевская атмосфера (LUT)
           + L_fogInscatter(dir)        — интеграл тумана (P10)
           + L_skyLayers(dir)           — слои мира (глаз, дальние структуры)
```

`L_atmosphere` — предвычисленные LUT по Хиллеру/Брунетону (`transmittance`, `scattering`, `irradiance`), 256×64 / 32×32×16. Это даёт **физически корректный цвет неба** и корректный цвет солнца на восходе/закате — важный вклад в тёплую палитру (§2.1.4).

**Но:** в этих референсах туман настолько плотный, что вклад `L_atmosphere` в нижней половине неба **мал** (≈ 10–20%). Основной вклад — `L_fogInscatter`. Поэтому:

```
Требование: обе компоненты обязательны, но их вклад должен автоматически
перераспределяться по дистанции/высоте. При σ→0 сцена даёт нормальное небо;
при σ→0.019 — небо становится «белой стеной», как на референсе.
```

## 4.2. Слои неба (для «глаза» и дальних структур)

**8–12 купольных слоёв** (HalfSphere mesh, 32×16 сегментов, инвертированная отсечка), каждый:

- своя альтитуда/азимут привязки;
- **параллакс** от положения камеры: `uv += cameraXZ * layer.parallaxFactor * 1e-5`;
- собственный материал: аддитивный / альфа / «fog-interacting»;
- **обязательная интеграция с туманом**: слои рисуются ДО композита тумана (P10) → туман ложится поверх них корректно. Слой в 2 км от камеры автоматически «утонет» в тумане, слой в зените — останется видимым. **Это ключ к тому, что «глаз» виден в небе, но структуры у горизонта — нет.**

**Правило:** ни один слой неба не имеет права рисоваться поверх композита тумана (кроме явного флага `overlay: true` для UI-подобных элементов).

## 4.3. Гало/радуги/световые столбы (опционально, Tier A/B)

При `σ` тумана и низком солнце автоматически:
- **гало 22°** — угловая зависимость в фазовой функции ледяных кристаллов;
- **световой столб** над солнцем — вертикальная вытянутость в фазовой функции;
- **радуга** — при дожде + солнце (каустика в капле, фаз. функция).

Реализуется как отдельный член в `p(θ)` (§5.1). Дешёво, но добавляет «настоящести» на закатных кадрах.

# 5. ТУМАН — ЯДРО СИСТЕМЫ

## 5.1. Модель плотности

```
σ_t(x) = σ_base · H(y) · D(x,z) · W(t) + σ_local(x)
```

| Член | Формула | Назначение |
|---|---|---|
| `σ_base` | скаляр из профиля | Базовая плотность |
| `H(y)` | `exp(-max(0, y - y0)/h)` | Высотный профиль |
| `D(x,z)` | `0.75 + 0.5·FBM2(x/220, z/220, t/60)` | Пятнистость (облака тумана) |
| `W(t)` | `1 + 0.25·sin(2πt/T_breath)` | Дыхание мира |
| `σ_local` | Вклад «моря тумана» ниже `y_top`: `σ_sea · smoothstep(y_top+s, y_top-s, y)` | Резкий верхний край (референс 2) |
| Дефицит | `-σ_clear` в зонах ясности (из профиля) | Пустоты/просветы |

**Дополнительно (§2.1.2):** плотность масштабируется **высотой над источником света**, что даёт затемнение в глубине моря:
```
σ_t *= (0.55 + 0.45 · saturate(L_ambient(y) / L_ambient(y_top)))
```

## 5.2. Фроксельная сетка

**Что такое фроксель:** элемент 3D-сетки, выровненной по экрану (`XY` = экранные тайлы, `Z` = слайс вдоль луча). Это позволяет вычислять туман **один раз на крупную ячейку экрана**, а не на каждый пиксель.

### Параметры

| Параметр | Tier C | Tier B | Tier A |
|---|---|---|---|
| Разрешение XY (тайл) | 96×54 (@540p/... ) | 160×120 | 240×135 |
| Слайсов Z | 32 | 48 | 64 |
| Формат | RGBA16F | RGBA16F | RGBA16F |
| Атлас | 768×432 | **1280×720** | 1920×810 |
| Обновление | 1/2 кадров | каждый кадр | каждый кадр |
| Композит-шагов | 8 | 16 | 24 |
| Временная репроекция | нет | да | да |

### Распределение по Z (обязательная формула)

Логарифмическое, чтобы ближняя зона имела разрешение:

```
z(i) = z_near · (z_far/z_near)^(i/(N-1)),   z_near = 0.05 м, z_far = 512 м
обратно:  i(z) = (N-1) · ln(z/z_near) / ln(z_far/z_near)
```

## 5.3. Как 3D-объём живёт в OpenGL 3.2 **без** 3D-текстур и compute

**Проблема:** `ShaderInstance.apply()` в 1.20.1 связывает **только `GL_TEXTURE_2D`** — передать `sampler3D` в шейдер через штатный механизм невозможно. `imageStore`, SSBO и компьют-шейдеры требуют GL 4.2+, а программный растеризатор на CI-стенде не имеет compute вообще.

**Решение — «фроксельный атлас»:** 48 слайсов выкладываются тайлами в **одну 2D-текстуру**.

```
Атлас 1280×720 RGBA16F, сетка 8 колонок × 6 строк = 48 тайлов по 160×120.

Генерация: ОДИН fullscreen-draw в атлас.
  В фрагментном шейдере:
      slice   = floor(gl_FragCoord.y / 120.0);            // 0..47
      tileX   = floor(gl_FragCoord.x / 160.0);            // 0..7
      tileY   = slice mod 6;      tileCol = slice / 6;    // раскладка
      uvXY    = vec2(fract(gl_FragCoord.x/160.0), fract(gl_FragCoord.y/120.0));
      z       = zNear * pow(zFar/zNear, (slice+0.5)/48.0);
      worldPos = reconstruct(uvXY, z);
      → density, light, запись (L·σ·dz, σ·dz)
```

**Никаких geometry-шейдеров, никаких `imageStore`, никаких 3D-текстур.** Совместимо с GL 3.2 Core и с `ShaderInstance`.

### Сэмплирование в композите

```glsl
// 2 билинейных сэмпла вместо одного трилинейного (границы тайлов не текут)
vec4 sampleFroxel(vec2 screenUV, float depth) {
    float fi = sliceCoord(depth);              // 0..47 (дробное)
    float f0 = floor(fi), fr = fi - f0;
    // половина тексела внутрь тайла — иначе утечка между тайлами
    vec2 uvIn = clamp(screenUV, vec2(0.5/160.0), vec2(1.0-0.5/160.0));
    vec4 a = texture(Atlas, atlasUV(f0,     uvIn));
    vec4 b = texture(Atlas, atlasUV(min(f0+1.0, 47.0), uvIn));
    return mix(a, b, fr);
}
```

**Обязательно:** `GL_CLAMP_TO_EDGE` + `GL_LINEAR`, **без мипмапов** (мипмапы перемешают тайлы).

### Ветка Tier A (опционально, только GL 4.3+)

Настоящая `sampler3D` + compute-генерация. Обязательства:
- полностью **опциональна**, за флагом `enableCompute = auto|on|off`;
- при `auto` — детект `GL_ARB_compute_shader` + успешная компиляция + smoke-test кадра;
- **при любой ошибке — молчаливый откат на атлас**;
- в CI обязателен прогон **обоих** путей (эталонный — атлас/llvmpipe).

## 5.4. Генерация фрокселей (что считается)

```glsl
void main() {
    // 1. Реконструкция мирового положения центра слайса
    vec3 wp = worldFromFroxel(uvXY, z);

    // 2. Плотность
    float d = densityModel(wp);                 // §5.1
    if (d < 1e-4) { outColor = vec4(0.0); return; }   // ← ранний выход, критично для скорости

    // 3. Освещение
    vec3 L = vec3(0.0);
    L += sunScatter(wp);                         // §6.1  (тень — heightfield-прокси §6.5)
    L += eyeBeamScatter(wp);                     // §6.3
    L += pointLightsScatter(wp, sliceIndex);     // §6.2  (список на слайс!)
    L += emissiveBlocksScatter(wp);              // §6.4
    L += ambientScatter(wp);                     // LUT атмосферы

    // 4. Многократное рассеяние — октавами (Wrenninge/Hillaire, 3 октавы)
    L = multiScatterOctaves(L, d);

    // 5. Упаковка: интегрируем ВНУТРИ слайса
    float dz = sliceThickness(slice);
    float T  = exp(-d * dz);
    vec3  Li = L * (1.0 - T);                    // ∫L·σ·dz для этого слайса
    outColor = vec4(Li, 1.0 - T);                // (свет, поглощение)
}
```

**Ранний выход при нулевой плотности — ключевая оптимизация.** В открытых зонах до 70% фрокселей пусты и не стоят ничего: пишем ноль, не считаем свет.

## 5.5. Композит (P10)

```glsl
vec3 composite(vec2 uv, vec3 sceneColor, float depth) {
    float z = linearize(depth);
    vec4 acc = vec4(0.0);
    float T = 1.0;

    // 1. Марш по фрокселям (16 шагов, джиттер по blue noise + temporal)
    float jitter = blueNoise(uv * screenSize) - 0.5;
    for (int i = 0; i < STEPS; i++) {
        float t = (float(i) + 0.5 + jitter) / float(STEPS);
        float zs = mix(zNear, min(z, zFar), t*t);       // нелинейно: мельче у камеры
        vec4 f = sampleFroxel(uv, zs);
        acc.rgb += T * f.rgb;
        T *= (1.0 - f.a);
        if (T < 0.004) break;                            // ранний выход
    }

    // 2. Аналитический хвост (z > zFar — «стена тумана», §2.1.3)
    vec3 dir = viewRay(uv);
    vec4 tail = analyticFogTail(cameraPos, dir, max(z - zFar, 0.0));
    acc.rgb += T * tail.rgb;
    T *= (1.0 - tail.a);

    return sceneColor * T + acc.rgb;
}
```

### Аналитический хвост — обязателен

Для экспоненциального высотного профиля вдоль луча:

```
Пусть  Δy = dir.y · t,  y(t) = y0 + Δy
σ(t) = σ0 · exp(-(y(t) - ybase)/h) = A · exp(-B·t)
∫_0^∞ A·exp(-B·t) dt = A/B      (при B > 0)
∫_0^{t1} σ dt = A·(1 - exp(-B·t1))/B
```

где `A = σ0·exp(-(y0 - ybase)/h)`, `B = dir.y·σ0/h` (с учётом `D(x,z)` — считать как среднее по лучу, 2–3 пробы).

**При `dir.y → 0` (луч к горизонту) `B → 0` и `∫ → ∞`: `T → 0`.** Это и есть «стена тумана» из референса. Для лучей вверх (`dir.y > 0`) интеграл сходится → небо видно, но размыто. **Именно эта одна формула даёт всю разницу между «серым туманом» и «белой стеной» в кадре.**

**Практическая защита:** при `|dir.y| < 1e-4` использовать `t_max = 8000 м` (не «∞»), иначе NaN. Отдельный unit-тест на это (см. §17).

## 5.6. Специальные виды тумана

| Вид | Реализация |
|---|---|
| **Море тумана снизу** (референс 2) | `σ_local` с резкой верхней границей + шум на границе (`smoothstep(top+s, top-s, y)`), плюс модуляция края 3D-шумом (пена/клубы на поверхности) |
| **Туман в низинах** | `H(y)` с `y0 = уровня воды/пола`, «заливка» по рельефу через heightfield |
| **Подводный** | Подмена профиля целиком: `σ` ×6, поглощение по каналам (красный гасится первым), `anisotropy` выше, `ambient` приглушён. Плюс искажение по волнам (§7.4) |
| **Whiteout** | Резкое `σ → 1.0` внутри зоны + **отсечение рендера** (§15.7): при видимости < 32 м не рисуем LOD 1+ |
| **Дымка/мгла** | Низкая `σ` (0.001–0.004), большой `h`, влияет в основном на дальние силуэты |

## 5.7. Почему не через ванильный `fog.fsh`

| Вариант | Вердикт |
|---|---|
| **A. `ViewportEvent.RenderFog` + пост-композит по глубине** | ✅ **Выбран.** `RenderFog` отменяет ванильный туман (или отодвигает до ∞), всё делаем сами |
| **B. Встроенный ресурспак с `minecraft:shaders/core/fog.fsh`** | ⚠️ Возможно с 1.20.1 (`AddPackFindersEvent`), но: несовместимо с любыми шейдерпаками/модификациями core-шейдеров, требует `varying` мировых координат от вершинного шейдера, конфликтует с Optifine/Iris. **Только как опциональная ветка, выключенная по умолчанию** |
| **C. Миксин в `FogRenderer`** | ⚠️ Может конфликтовать с другими модами. Допустим только для отмены ванильного тумана, не для математики |

**Ванильный туман в 1.20.1 вычисляется по расстоянию и не знает мировой Y** (нет мировых координат в `fog.fsh`) — значит высотный туман через него принципиально невозможен. Это и есть главная причина выбора варианта A.

# 6. ОБЪЁМНЫЙ СВЕТ

Всё объёмное освещение живёт **внутри фроксельной генерации** (P6) — это даёт нулевую дополнительную стоимость проходов и автоматическую согласованность с туманом. Дополнительные пассы (screen-space god rays) — только как fallback для Tier C.

## 6.1. Солнце и луна

```glsl
vec3 sunScatter(vec3 wp) {
    // 1. Тень (heightfield-прокси, §6.5)
    float shadow = terrainShadow(wp, sunDir);       // 0..1

    // 2. Оптическая толща до источника (по плотности, 3–4 пробы)
    float tau = densityTauToSun(wp);

    // 3. Фазовая функция (§6.6)
    float phase = phaseHG(dot(viewDir, sunDir), g);

    // 4. Энергия
    return sunColor * sunIntensity * shadow * phase
         * exp(-tau) * scatterAlbedo;
}
```

**Рассеяние Луны отдельно не пишется** — луна это тот же `sunScatter` с другой интенсивностью/цветом и флагом `moonScatter` (сильнее forward-scattering, ниже интенсивность).

## 6.2. Точечные источники (свечение фонарей в тумане — фича референса)

```glsl
vec3 pointLight(vec3 wp, Light l) {
    vec3  d  = l.pos - wp;
    float r2 = dot(d, d);
    if (r2 > l.radius2) return vec3(0.0);               // отсечка по радиусу
    float att = l.intensity / max(r2, 0.25);            // 1/r² (не 1/r)
    float phase = phaseHG(dot(normalize(d), viewDir), 0.0);   // isotropic+лёгкий forward
    return l.color * att * phase * exp(-densityTauSlant(wp, l.pos));
}
```

**Обязательные детали:**
- **`1/r²`, а не `1/r`** — иначе ореол фонаря будет плоским. На референсе видно чёткое затухание.
- **Список на слайс** (не глобальный список!). CPU раз в кадр считает, какие источники пересекают диапазон Z каждого из 48 слайсов, и передаёт `uLightCount[48]` + `uLightIndex[48×8]`. В среднем на слайс приходится 2–4 источника вместо 32 → **ускорение ~8×**.
- **Максимум 8 источников на слайс**, сортировка по вкладу `intensity/radius²`.
- Источники с флагом `volumetric: false` **не попадают** в туман (только освещают геометрию).

**Проверка результата:** ядро ореола после тонмаппинга должно попадать в диапазон **`#984A4A`…`#B96B6D`** (§2.1.6). Это измеримо и вносится в гейт G5.

## 6.3. Лучи из «глаза» (уникальная фича этого мода)

«Глаз» в небе — не просто декорация: он **источник направленного света**. Реализуется как **конусный источник (spot) с огромным углом и отрицательной `attenuation`**:

```glsl
vec3 eyeBeam(vec3 wp) {
    vec3  toEye = normalize(eyePos - wp);
    float cosA  = dot(-toEye, eyeDir);
    float cone  = smoothstep(cosEyeOuter, cosEyeInner, cosA);   // мягкий конус
    float tau   = densityTauSlant(wp, eyePos);
    float flick = 0.85 + 0.15 * sin(t * 2π / 27.0);              // «дыхание» 27 с
    return eyeColor * eyeIntensity * cone * flick * exp(-tau);
}
```

**Требования:**
- В конусе появляется **видимый световой столб** в тумане — это сильнейший вау-эффект и он **обязателен** (гейт G6).
- Интенсивность затухает при погружении в туман (по `exp(-tau)`) — глаз **гаснет первым**, как и требуется в §2.1.7.
- Конус не должен давать жёстких границ: `cosEyeOuter → cosEyeInner` — минимум 0.25 разницы по косинусу.

## 6.4. Эмиссивные блоки и объекты

Всё, что светится (фонари, лава, кристаллы, редстоун), обязано **отдавать свет в туман**. Механизм:

1. Хост-мод (или автоматический сканер чанков) регистрирует эмиссивные блоки через `VolFx.addLight(...)`.
2. Модуль агрегирует их: блоки в радиусе 24 блоков, с одинаковым цветом, **сливаются в один источник** (крупные скопления фонарей не должны давать 200 источников).
3. Приоритет по `intensity = Σ(emission) / (1 + r²)`.
4. **Автосканирование (опция, дефолт — вкл.:** раз в 1 с сканируется область вокруг игрока 64×64×48, блоки с `LightEmission ≥ 10` и «тёплым» цветом (из `BlockColors`/карты блоков) становятся источниками. Это то, что даёт в кадре автоматически **правильные красные ореолы вокруг фонарей** без ручной расстановки.

## 6.5. Тени в тумане без shadow map

Полноценный CSM-шэдоумап для 1.20.1 — дорого и конфликтно. Используем **heightfield-прокси**:

```
1. Раз в 4 кадра строится heightfield 256×256 (1024 блока) вокруг игрока:
   для каждого столбца — максимальная высота непрозрачного блока (из данных чанков,
   без рендера).
2. terrainShadow(wp, sunDir): 6–10 шагов марша по направлению солнца,
   сравнение y с heightfield[y] → 0/1, сглаживание по 4 соседям.
3. Результат сэмплируется во фроксель-пассе.
```

**Что это даёт:** туман **под** парящим островом темнее, туман в тени острова темнее. Именно это создаёт «объёмность» моря тумана на референсе 2. Без этого море тумана выглядит плоским пятном.

**Что это НЕ даёт:** корректные резкие тени от мелких объектов (их в тумане и не видно) и самозатенение облаков. Честно указано в ограничениях (§20).

**Опционально Tier A:** настоящий шэдоумап для солнца (1 каскад, 2048², обновление по смещению солнца на > 0.5°), использующийся только для тумана. **Не обязателен.**

## 6.6. Фазовые функции

```glsl
// Хени-Гринштейн
float phaseHG(float cosT, float g) {
    float g2 = g*g;
    return (1.0 - g2) / (4.0 * PI * pow(1.0 + g2 - 2.0*g*cosT, 1.5));
}
// Смесь двух лопастей (дождь/пыль/лёд)
float phaseDual(float cosT, float gf, float gb, float mix) {
    return mix * phaseHG(cosT, gf) + (1.0-mix) * phaseHG(cosT, gb);
}
```

| Среда | `g` | Причина |
|---|---|---|
| Туман капельный | `0.45` + dual `(-0.35, 0.8)` | Видны и лучи к солнцу, и «серебряная кайма» |
| Дымка/аэрозоль | `0.60` | Сильное forward |
| Ледяные кристаллы (гало) | `0.75` + узкие пики | Гало 22° |
| Подводный | `0.30` | Меньше forward в плотной среде |

## 6.7. Многократное рассеяние

Аппроксимация октавами (Wrenninge / Hillaire) — 3 октавы:

```glsl
vec3 multiScatterOctaves(vec3 L, float d, float albedo) {
    vec3  acc = L; float a = 0.5; float sig = 1.0;
    for (int i = 1; i < 3; i++) {
        acc += L * a * multiScatterLUT(i);   // LUT 32×32: (octave, extinction) → energy
        a *= 0.5;
    }
    return acc * mix(1.0, 1.35, saturate(d * 40.0));  // плотный туман «подсвечивается изнутри»
}
```

**Зачем:** без этого плотный туман становится **слишком тёмным** (однорассеяние не возвращает свет). На референсе море тумана **светлое** — это прямое следствие многократного рассеяния. **Обязательно.**

# 7. ОТРАЖЕНИЯ И ВОДА

## 7.1. Плоское зеркало (водоёмы, зеркальный пол)

Для плоскости `y = planeY` зеркальная камера строится отражением:

```
P' = reflect(P, plane);   V' = reflect(V, plane)   (плюс инверсия основы, чтобы сохранить «право»)
```

### Пайплайн прохода (P5)

```
1. Guard: if (alreadyRenderingReflection) return;   ← ОБЯЗАТЕЛЬНО (иначе бесконечная рекурсия)
2. Свой FBO 0.5× (RGBA16F + DEPTH24)
3. Загрузить матрицы зеркальной камеры (view = reflected, proj = oblique near plane)
4. glCullFace(FRONT)   ← инверсия намотки, иначе вся геометрия вывернута
5. Рендер: небо → мир непрозрачное → прозрачное (БЕЗ отражений, БЕЗ пара)
6. Обязательно: внутри этого прохода работают те же фроксели (туман мировой ⇒ верен автоматически)
7. Восстановить: cull face, FBO, матрицы, состояние GlStateManager
```

**Косое отсечение near-плоскости (Lengyel)** — обязательна: без него в отражение попадает всё, что **ниже** плоскости (подводный мир/изнанка), и картинка искажается.

```java
// Классическая модификация проекции под плоскость отражения
Vector4f clipPlane = new Vector4f(0, 1, 0, -planeY);   // в пространстве камеры отражения
proj.mul(clipPlaneObliqueMatrix(clipPlane));
```

### Разрешение и частота обновления

| Tier | Разрешение | Частота | Уточнение |
|---|---|---|---|
| C | 0.25× | 10 Гц | + SSR-добор |
| B | **0.5×** | 20 Гц или при смещении камеры > 0.05 блока | дефолт |
| A | 0.75× | каждый кадр | + SSR |

**Временнáя стабильность:** отражение обновляется не каждый кадр → обязательна **асинхронная интерполяция**: при обновлении сохраняется матрица отражения, при использовании — репроекция по движению камеры между кадрами (иначе отражение будет «дёргаться» при ходьбе). Это критично, отдельный гейт (G7 проверяет стабильность отражения между кадрами).

### Ослабление отражения

На референсе `world4_mirror` измерено: объект 95.9 яркости → отражение 70.6, **отношение 0.74**. Это не «прозрачное стекло», а **поглощающая среда**:

```
отражение = отражённый_свет · K_reflect · tint(absorption)
K_reflect  ≈ 0.72          (измерено!)
absorption ≈ exp(-σ_abs · 2 · depth)  — красный гасится первым
tint       ≈ [0.34, 0.38, 0.40]       (измеренный #272B2D пол)
```

Формально: `#272B2D / #464544` по каналам → тёмный, слегка холодный пол. **Обязательно воспроизвести это соотношение** (гейт G7, допуск ±8%).

## 7.2. Вариант Б: «зеркальный мир» как отдельная геометрия

Если в вашем моде отражённый мир — **это не отражение, а реально существующая вторая половина мира** (отдельное измерение/инстанс, видимое сквозь прозрачный пол — а на референсе 1 это похоже именно на это: в отражении видны структуры, которых нет сверху), то проход P5 **не нужен вообще**. Вместо него:

```
1. Пол рисуется как ПРОЗРАЧНЫЙ блок с собственным материалом (absorption + fresnel)
2. Нижний мир рендерится штатно (это часть мира, если он в том же измерении,
   или отдельный инстанс-рендер, если это копия)
3. Туман/поглощение между камерой и нижним миром считается тем же кодом
   (фроксель-интеграл по отрезку камера→фрагмент пола + по отрезку пол→низ)
4. Риплы на полу искажают проекцию (программное смещение UV)
```

**Как выбрать:** если нижний мир — это буквально ваша собственная копия верхнего, вариант Б даёт **бесплатное** идеальное отражение (0 мс вместо ~1.2 мс) и работает на любом железе. Рекомендуется к использованию, если структура мода это позволяет.

## 7.3. SSR (для не-плоских поверхностей)

Для мокрого камня, льда, полированных блоков. Экранный марш по `depthCopy` (12–24 шага), с:
- бинарным уточнением на границе;
- отсечением по толщине (объект за плоскостью игнорируется);
- смешиванием с cubemap/константой при неудаче (но SSR — **только добавка**, никогда не единственный источник: при повороте камеры он «моргает»).

**Приоритет:** плоское отражение > SSR > фейковое (ambient). Никогда не смешивать SSR и плоское для одной и той же поверхности.

## 7.4. Поверхность воды

```glsl
vec3 waterSurface(vec2 uv, vec3 viewDir) {
    // 1. Нормаль: сумма двух-трёх слоёв нормалей-ряби
    vec3 n = normalize(vec3(
        ripple(uv*1.0, t*0.7).xy * 1.00 +
        ripple(uv*3.7, t*1.3).xy * 0.35 +
        ripple(uv*11.0, t*2.1).xy * 0.12, 1.0));

    // 2. Френель Шлика
    float F = 0.02 + 0.98 * pow(1.0 - max(0.0, dot(n, viewDir)), 5.0);

    // 3. Отражение (плоское, с лёгким размытием по шероховатости)
    vec3 refl = sampleMirror(uv + n.xz * distScale, roughness);

    // 4. Преломление + поглощение по глубине (пик глубины через depthCopy)
    float depth = sceneDepth(uv) - waterDepth(uv);
    vec3 refr = sceneColor(uv + n.xz * refractionScale) * exp(-absorbRGB * depth);

    // 5. Смешивание
    return mix(refr, refl, F);
}
```

**Обязательные детали:**
- **Каустики (опция):** анимированная текстура-каустика, проецируемая на дно в мировых координатах (не экранно!) — `caustic(worldXZ * k + flow(t))`, умноженная на глубину. Экранная каустика «прилипает» — брак.
- **Береговая линия:** тонкая полоса пены/замутнения у пересечения с геометрией (по разнице глубины), толщина ~0.15 блока.
- **Рябь взаимодействует с туманом:** нормаль воды должна влиять на направление, по которому берётся фроксель (иначе в тумане вода выглядит «плоской плёнкой»).

## 7.5. Подводная среда

При `camera.y < waterLevel`:

| Компонент | Значение |
|---|---|
| Туман | `σ` × 5–8, поглощение по каналам: `[0.45, 0.08, 0.04]` → красный исчезает первым |
| Цвет | Сдвиг ambient в сторону профиля погружения (для этого мода — тёплый, не синий) |
| Лучи | Солнечные лучи через поверхность: `σ` велик ⇒ лучи становятся широкими и мягкими (автоматически, из фрокселей) |
| Искажение | Экранное искажение по нормалям ряби (амплитуда ∝ глубине под поверхностью) |
| Граница воды снизу | Всего внутреннего отражения: при угле > 48.6° поверхность становится зеркалом — реализуется через френель (уже даёт это автоматически) |
| Звук | Смена реверберации (§12) |

# 8. ПАР, ИСПАРЕНИЯ, ДЫМКА

## 8.1. Stateless GPU-частицы (главное проектное решение этого раздела)

**Проблема:** классические частицы требуют симуляции на CPU (позиции, скорость, время жизни) → аллокации, обновления буферов, ограничение по количеству.

**Решение:** пар — **чистая функция** от `(индекс, время, начальная точка)`:

```glsl
// Позиция частицы восстанавливается ЦЕЛИКОМ в вершинном шейдере
vec3 particlePos(uint id, float tNow) {
    uint seed = hash(id * 2654435761u);
    float t0  = rand01(seed) * emitter.period;                  // фаза рождения
    float life = emitter.life * (0.7 + 0.6*rand01(seed ^ 0x9E37u));
    float age = mod(tNow - t0, life);
    float k   = age / life;

    vec3 p = emitter.pos;
    p += vec3(rand01(seed^1u)-0.5, 0.0, rand01(seed^2u)-0.5) * emitter.radius;
    p.y += emitter.riseSpeed * age * (1.0 - 0.35*k);            // подъём с замедлением
    p += curlNoise(p * emitter.curlScale, tNow * emitter.curlSpeed) * emitter.curlAmp * age;
    p += windAt(p) * age;                                       // ветер мира (если есть)
    return p;
}
```

**Что это даёт:**
- **Ноль работы на CPU.** Один `glDrawArraysInstanced` с буфером из 4 вершин.
- **Ноль аллокаций в кадре**, ноль обновлений буферов.
- **Идеальная детерминированность** (важно для мультиплеера и для скриншотов-эталонов).
- 50 000+ частиц бесплатно (всё на GPU).

**Ограничение (честно):** частицы не взаимодействуют друг с другом и не сталкиваются с блоками — они проходят сквозь геометрию по прямой аналитической траектории. Для пара, испарений и дымки этого достаточно (мягкая полупрозрачная среда)
и это **сознательный компромисс ради нулевой стоимости на CPU**.
Если потребуется настоящая симуляция пара со столкновениями и взаимным влиянием —
она реализуется отдельным модулем через тот же `IVolFx` (расширение API резервируется, см. §13.9).

## 8.2. Освещение и туман для частиц

Каждая частица **сэмплит фроксель в своей позиции** — и получает ровно тот же туман и свет, что и мир:

```glsl
// во фрагментном шейдере частицы
vec4 f = sampleFroxelAtWorld(p);          // (L·σ·dz, σ·dz) в её точке
vec3 lit = particleColor * albedo * (uAmbient + sunLightAt(p));
vec3 finalColor = lit * (1.0 - f.a) + f.rgb;
```

**Следствие (и это ключевое):** пар **автоматически** получает правильный цвет в тумане, гаснет в глубине, светится рядом с фонарём. Никаких ручных «подкрасок под туман». Если туман изменился — пар изменился вместе с ним.

**Сортировка:** альфа-блендинг требует порядка. Решение — **OIT-free trick**: используется аддитивно-премноженный альфа-блендинг (`GL_ONE, GL_ONE_MINUS_SRC_ALPHA`) с малым alpha → ошибки порядка визуально неразличимы для мягкого пара. Для крупных близких клубов дополнительно CPU-сортировка по глубине (пул из ≤ 96 «крупных» частиц).

**Грабли 1.20.1 (обязательно учесть):** ванильный `ParticleEngine` выставляет `depthMask(true)` и отбрасывает фрагменты с `alpha < 0.1` — **поэтому пар физически не может рисоваться ванильными частицами**: мягкая полупрозрачная кромка будет жёстко отсечена. Только собственный пасс:
`depthMask(false)`, `depthTest(true)`, `blendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)`.

## 8.3. Soft particles (растворение в геометрии)

Без этого пар будет **резаться об блоками жёсткой кромкой** — самый заметный «дешёвый» артефакт.

```glsl
// depthCopy — копия глубины непрозрачной сцены (сделана ДО прозрачных)
float sceneZ = linearize(texture(depthCopy, screenUV).r);
float fade   = saturate((sceneZ - particleZ) / softDistance);   // softDistance ≈ 1.5 блока
alpha *= fade * fade;
```

**Обязательное требование:** копия глубины делается **до** рендера прозрачных объектов. В 1.20.1 `RenderTarget.copyDepthFrom(...)` **разбиндивает активный FBO (на 0)** — после вызова обязательна ручная привязка, иначе весь дальнейший рендер уйдёт «в никуда»:

```java
mirrorTarget.copyDepthFrom(mc.getMainRenderTarget());
GlStateManager._glBindFramebuffer(GL_FRAMEBUFFER, mc.getMainRenderTarget().frameBufferId);
```

## 8.4. Тонкие туманные шлейфы и слои

- **Вуали/завесы** (2–4 вертикальные полупрозрачные плоскости с анимированным шумом) — для «шёлковых» занавесов в тумане. Дешёвая, но очень выразительная деталь; должна получать свет из фрокселей.
- **Слои над поверхностью воды/пола** — очень низкие «плоскости» тумана 0.5–2 блока толщиной. Реализуемы как `σ_local` в модели плотности (предпочтительно) или как текстурированная плоскость (fallback Tier C).
- **Пылинки в свете** (light motes) — маленькие аддитивные точки, живые только внутри конуса источника. `0.02` блок/с дрейф. Порог: включать только при `sunIntensity >` порога и камере в конусе. **Очень дешёвый, очень «дорогой» по виду эффект.**

# 9. ПАРЯЩИЕ ОБЪЕКТЫ И ДЕБРИ (FX-СЛОЙ)

Парящие блоки в воздухе (референс 2) — часть мира, но **их поведение** в слое эффектов:

| Аспект | Требование |
|---|---|
| **Дрейф** | Медленное вращение (0.02–0.08 рад/с) + синусоидальное «дыхание» по Y (±0.15 блока, 8–20 с) + curl-noise дрейф |
| **Освещение** | Обычное освещение мира + вклад от фрокселей (объект в тумане темнеет и синеет/желтеет по профилю) |
| **Растворение** | По дистанции — плавное повышение альфы к цвету тумана на 60–220 м, полностью растворяться до 260 м |
| **Следы** | Медленно появляющиеся/исчезающие (alpha-fade 2–4 с) «искры»-частицы вокруг при появлении |
| **Отражение** | Парящие объекты над водой **обязаны** попадать в отражение (это самое заметное в референсе 1) |

# 10. НЕБО И «ГЛАЗ»

## 10.1. Композиция неба

```
L_sky = L_atmosphere(LUT)          — рэлеевская база, тёплый градиент
      + L_fogInscatter(фроксель)   — ГЛАВНЫЙ член (§2.1.1)
      + Σ L_skyLayer[i]            — купольные слои
```

Слои (порядок от дальнего к ближнему):

| # | Слой | Функция | Параллакс |
|---|---|---|---|
| 0 | Атмосферный LUT | физическое небо | нет |
| 1 | «Глаз» | главный сюжетный элемент | 0.02 |
| 2–4 | Дальние силуэты/структуры | глубина мира | 0.05 / 0.09 / 0.14 |
| 5–7 | Ближние вихри/завесы | объём | 0.25 |
| 8 | Верхние перистые полосы (опц.) | жизнь неба | 0.03 |

Все слои рисуются **до** композита тумана → автоматически тонут в нём по дистанции.

## 10.2. «Глаз» — обязательные требования

| Требование | Значение |
|---|---|
| Яркость ядра | `#DFDACD` (223, 218, 205) ± 4% |
| Контраст над фоном неба | **+34 ед. яркости** (измерено) ± 30% |
| Состав | несколько концентрических слоёв с разной альфой (не одна текстура с резкими краями) |
| Края | **только мягкие**: градиент ≥ 25 px на 1080p между «полностью виден» и «полностью прозрачен» |
| Дрейф | медленное смещение (0.02–0.05°/с), период полного оборота 2–6 ч игрового времени |
| Дыхание | масштаб зрачка `1 ± 0.06`, период 22–34 с (не синхронизирован с музыкой/событиями случайно — только детерминированно) |
| Взаимодействие с туманом | гаснет по `exp(-τ)` — при погружении в туман исчезает **раньше** структур |
| Не «приклеен к экрану» | обязательный параллакс; при движении камеры смещается относительно звёзд/облаков |
| Ночью | ярче (относительно потемневшего неба), но абсолютная яркость ниже дневной |

**Запрещено:** рисовать глаз в экранных координатах; рисовать жёсткий круг; использовать одну текстуру с чёткой альфой; обрезать слоем тумана.

## 10.3. События неба (опционально, за флагом)

Для «жизни» мира (не обязательны, но очень усиливают эффект):

- **Затмение/мигание глаза** — затемнение с 0.5–2 с, с последующим «выдохом» света (всплеск `eyeIntensity` + локальная волна в тумане).
- **Дрожь моря тумана** — при событии `σ` в море модулируется волной с фронтом, расходящимся от точки под глазом.
- **Появление/исчезновение парящих структур** — при `visibility > порога` (физически: они проявляются из тумана).

Все события — **детерминированные от мирового сида**, без `Math.random()`, с сохранением состояния в NBT.

# 11. ПОСТОБРАБОТКА

## 11.1. Порядок (обязательный)

```
scene_HDR  →  BLOOM  →  ЭКСПОЗИЦИЯ  →  ТОНМАППИНГ  →  ГРЕЙД(LUT)
           →  DOF  →  MOTION BLUR  →  ЗЕРНО  →  ВИНЬЕТКА  →  ХРОМАТИКА
           →  ДИЗЕРИНГ  →  LDR → UI
```

## 11.2. Экспозиция и тонмаппинг

```
Адаптация:  средняя логарифмическая яркость по гистограмме (64 корзины)
            speed_up  = 1.2 /с, speed_down = 0.35 /с   (асимметрия — как у глаза/камеры)
            clamp     = [-6, +4] EV от номинала
Тонмаппинг: ACES filmic (фит Стивена Хилла, матрицы обязательны — не «приблизительный ACES»)
```

**Почему ACES:** именно он даёт то «выцветание в белое» без клиппинга, что видно на референсах. Reinhard даст серость, линейный клип — плато `#FFFFFF` и потерю силуэтов (нарушение правила §2.4.7).

**Обязательно:** экспозиция **не должна «дышать»** при переходе между сценами. Гистерезис + ограничение скорости + блокировка адаптации на 0.5 с после телепорта/смены измерения.

## 11.3. Грейд (целевые числа из §2.2)

```glsl
vec3 grade(vec3 c) {
    c *= vec3(uExposure);
    c  = splitTone(c, uShadowTint, uHighlightTint);   // тени холоднее, света теплее
    c  = contrast(c, uContrast);                      // 1.04
    c  = saturate_desat(c, uSaturation);              // 0.88–0.92
    return texture(uLut3D, ...).rgb;                  // 3D LUT 32³ в 2D-атласе
}
```

**Целевые метрики выхода (проверяются гейтом G1/G2):**
- средняя насыщенность кадра: **0.09–0.13**;
- средняя яркость: **140–170**;
- доля пикселей с `R > G > B` в светах: ≥ 85%;
- красных пикселей (акцент): **≤ 0.5%**.

## 11.4. Bloom

Mip-chain 6 уровней (downsample 13-tap COD, upsample tent 9-tap) — стандарт, даёт гладкие ореолы без «блочности».

| Параметр | Значение |
|---|---|
| Порог | 0.85 (в HDR, после экспозиции) |
| Мягкое колено | 0.5 (обязательно: без колена — «звёзды» на фонарях) |
| Интенсивность | 0.35 |
| Радиус | 12 px (эквивалент) |

**Обязательное ограничение:** bloom **не должен** поднимать яркость неба (иначе правило §2.4.3 «света тёплые, но не выжженные» ломается). Вклад bloom в области с яркостью > 0.9 ограничивается (`soft-knee saturation`).

## 11.5. Дизеринг — обязателен (§2.1.5)

```glsl
// blue noise 64×64, смена тайла каждый кадр (temporal rotation по Байеру-золотому сечению)
const float DITHER_AMP = 1.0/255.0;
color += (texture(blueNoise, screenUV*vec2(W,H)/64.0 + frameOffset).r - 0.5) * DITHER_AMP;
```

**Почему критично:** изображения на 90% состоят из гладких градиентов. На 8-битном выходе без дизеринга обязаны появиться полосы — и они **мгновенно убивают вид** (это первое, что заметит любой на скриншоте). Проверяется гейтом G8 количественно (§17).

**Требование:** временнóй дизеринг (смещение тайла каждый кадр), иначе шум «залипает» и виден как статичная сетка.

## 11.6. Прочие эффекты

| Эффект | Параметр | Обязательность |
|---|---|---|
| Виньетка | 0.18, мягкая, эллиптическая | да |
| Зерно | 0.010 амплитуда, размер 1.0 px, анимированное | да |
| Хроматическая аберрация | 0.5 px к краям | опционально |
| Дисторсия | 0.005 (едва заметно) | опционально |
| DOF | фокус по глубине, CoC 6 px макс | опционально (Tier A/B) |
| Motion blur | 8 сэмплов, только от движения камеры | опционально (Tier A) |
| Линзовые пятна (lens dirt) | 1 текстура, только на ярких источниках | опционально |

**Запрещено:** пересвет (bloom+grade), «рыбий глаз», сильная хроматика. Стиль референса — **сдержанный**.

# 12. ЗВУК И ОБРАТНАЯ СВЯЗЬ

Звук — часть «эффекта присутствия», и он дёшев.

| Событие | Звук | Обработка |
|---|---|---|
| Камера в тумане (`τ > 1.5`) | Приглушение всех звуков | Low-pass фильтр, `cutoff = 8000·exp(-τ·0.35)` Гц — **физически верно** (поглощение ВЧ в тумане) |
| Море тумана | Очень низкий гул 25–60 Гц | Амплитуда ∝ близости к границе моря |
| Фонари | Тёплый «электрический» гул, `1/r²` | — |
| Глаз (событие) | Инфразвуковой удар + длинный реверб | Триггерится событием §10.3 |
| Вода | Приглушение под водой (`cutoff 500 Гц`) + всплеск на входе | — |
| Дебри/парящие объекты | Тихий ветер вокруг | `∝` скорости дрейфа |

**Реализация:** Forge `SoundEvent` + собственный `SoundInstance` с фильтром. **Обязательное требование:** фильтр применяется **по оптической толще** (`τ`) между камерой и источником. Это то, что заставляет игрока **чувствовать** туман, а не только видеть его.

**Обязательно:** визуальная обратная связь — при `τ > 2.5` интерфейсные маркеры/частицы гаснут, при `τ > 4` вводится «whiteout»-режим (§15.7). Игрок должен понимать, что он потерял ориентацию — но не получать за это урон и не «залипать».

# 13. ИНТЕГРАЦИЯ В СУЩЕСТВУЮЩИЙ МОД

> **Это главный раздел документа.** Здесь описано, как именно всё из §4–§12
> попадает в уже существующий мод. Хост-мод **не переписывается**: к нему
> добавляется один новый пакет `hostmod/effects/` и три вызова.
> Весь остальной код — внутри модуля эффектов.

## 13.1. Публичный API

```java
package com.volfx.api;

public interface IVolFx {

    // ── Инициализация ────────────────────────────────────────────────────
    void init(VolFxConfig cfg);

    // ── Состояние мира (обязательные) ────────────────────────────────────
    void tick(ClientLevel level, Entity cameraEntity);
    void setAtmosphere(ResourceKey<Level> dim, AtmosphereProfile profile);
    void setSkyOverride(ResourceKey<Level> dim, SkyProfile sky);

    // ── Регистрация эффектов (опциональные) ──────────────────────────────
    MirrorHandle    registerMirror(MirrorPlane plane);
    LightHandle     addLight(PointLight light);
    EmitterHandle   addSteamEmitter(SteamEmitter e);
    VeilHandle      addVeil(Veil veil);
    void            remove(EffectHandle h);

    // ── События (одноразовые) ────────────────────────────────────────────
    void flash(FlashEvent e);          // разовая вспышка света в тумане (молния, событие мира)

    // ── Запросы (безопасны из главного потока, возвращают иммутабельные данные) ──
    float fogDensityAt(Vec3 pos);
    float fogTransmittance(Vec3 from, Vec3 to);
    Vec3  inscatterAt(Vec3 pos, Vec3 viewDir);
    float visibilityAt(Vec3 pos);      // метры — для геймплея, ИИ, HUD

    // ── Управление ───────────────────────────────────────────────────────
    void setQuality(QualityTier tier);
    QualityTier quality();
    void reloadProfiles();
    VolFxDiagnostics diagnostics();    // метрики кадра, §17.3
}
```

**Обязательное свойство:** существует реализация `NoopVolFx`, которая **не делает ничего**
и возвращает безопасные значения (`fogDensityAt → 0`, `visibilityAt → 10000`,
все `register*` → пустой handle). Хост-мод линкуется с ней и работает **ровно как раньше**,
если модуль не установлен. Это ключ к тому, что интеграция не ломает мод.

```java
// Хост всегда берёт реализацию отсюда — и никогда не проверяет ModList вручную:
IVolFx FX = VolFxFactory.get();   // есть модуль → настоящая реализация; нет → NoopVolFx
```

| # | Что вызывает хост-мод | Когда | Обязательно? |
|---|---|---|---|
| 1 | `FX.init(cfg)` | клиентский setup | **да** |
| 2 | `FX.tick(level, camera)` | `ClientTickEvent.End` | **да** |
| 3 | `FX.setAtmosphere(dim, profile)` | вход в измерение / `LevelEvent.Load` | **да** |
| 4 | `FX.setSkyOverride(dim, sky)` | если у измерения своё небо | нет |
| 5 | `FX.registerMirror(...)` | создание зеркального пола/воды | нет |

## 13.3. Данные, а не код

90% настройки — **JSON-профили**, читаемые из `config/volfx/` и из датапаков:

```
config/volfx/
├── profiles/
│   ├── mirror_world.json     ← атмосфера измерения «зеркальный мир»
│   ├── void_world.json       ← атмосфера измерения «пустота»
│   ├── underwater.json       ← подводная среда
│   └── ...
├── skies/
│   ├── eye_mirror.json       ← слои неба + параметры «глаза»
│   └── eye_void.json
├── blocks.json               ← какие блоки светят и как (свет, пар)
├── grade/
│   ├── day.cube              ← 3D LUT для дня
│   ├── night.cube
│   └── event.cube
└── selector.json             ← правила: какой профиль когда (измерение/время/высота/событие)
```

Это значит:

- новый мир с туманом добавляется **без компиляции** — правкой JSON;
- цвет/плотность/грейд подкручиваются **без пересборки** — `/volfx reload`;
- разные профили для дня, ночи, события — селектором, а не кодом.

```json

  "rules": [
    { "when": { "dimension": "hostmod:mirror_world", "time": "day" },   "profile": "mirror_world" },
    { "when": { "dimension": "hostmod:mirror_world", "time": "night" }, "profile": "mirror_world_night" },
    { "when": { "dimension": "hostmod:void_world", "below_y": 40 },      "profile": "void_sea" },
    { "when": { "camera_underwater": true }, "profile": "underwater" }
  ]
}
```

## 13.4. Адаптация к пайплайну хоста

Если у хоста **уже есть** собственный HDR-таргет или свой рендер-пайплайн:

| Режим | Когда | Что делает модуль |
|---|---|---|
| `standalone` | у хоста обычный рендер | создаёт свои таргеты, делает финальный блит в главный таргет |
| `external` | у хоста свой HDR-пайплайн | **не создаёт** таргеты, рисует в переданные, не делает блит |

```java
// хост с собственным пайплайном:
VolFx.attach(ExternalTargets.builder()
    .hdrColor(myHdrFbo, myHdrTexture)
    .depth(myDepthTexture)
    .screenSize(myWidth, myHeight)
    .build());
```

**Требование:** оба режима дают **идентичный скриншот** (проверяется гейтом G1 в двух
прогонах, `pixel diff < 1%`). Это защищает от «в external забыли половину эффектов».

### Шаг 1. Подключение модуля


### Шаг 2. Три обязательных вызова (весь код хоста)

Создаётся **один новый класс** в хосте. Больше хост-код не меняется нигде.

```java
package com.hostmod.effects;

public final class HostEffects {

    public static final IVolFx FX = VolFxFactory.get();   // NoopVolFx, если модуля нет

    @SubscribeEvent
    static void onClientSetup(FMLClientSetupEvent e) {
        FX.init(VolFxConfig.load());                       // (1) инициализация
    }

    @SubscribeEvent
    static void onClientTick(TickEvent.ClientTickEvent e) {
        if (e.phase != TickEvent.Phase.END) return;
        Minecraft mc = Minecraft.getInstance();
        if (mc.level == null || mc.isPaused()) return;
        FX.tick(mc.level, mc.getCameraEntity());            // (2) тик
    }

    @SubscribeEvent
    static void onLevelLoad(LevelEvent.Load e) {
        if (!e.getLevel().isClientSide()) return;
        ResourceKey<Level> dim = e.getLevel().dimension();
        FX.setAtmosphere(dim, AtmosphereProfile.byDimension(dim));   // (3) атмосфера
        FX.setSkyOverride(dim, SkyProfile.byDimension(dim));         //     небо (опц.)
    }
}
```

**Проверка шага 2:** в логе — инициализация; `/volfx debug hud` показывает ненулевые
цифры (пассы выполняются), картинка пока **не изменилась**.

### Шаг 3. Профили атмосферы для каждого измерения

Кладём `config/volfx/profiles/<имя>.json` по шаблону §2.3. Минимум для начала:

```json
{
  "id": "mirror_world",
  "fog": {
    "sigma0": 0.019,
    "baseY": 62.0,
    "heightFalloff": 55.0,
    "scatterAlbedo": [1.00, 0.982, 0.930],
    "anisotropy": 0.45,
    "farTailMode": "analytic_saturating"
  },
  "grade": { "exposure": 1.05, "tonemap": "ACES_fit", "saturation": 0.88 }
}
```

**Проверка шага 3:** в игре появляется туман; горизонт **исчезает** (это признак,
что аналитический хвост работает — §5.5). Если горизонт виден полосой — хвост не включён.

**Частая ошибка:** задать `sigma0` «на глаз» маленьким (0.002) и решить, что туман не
работает. Целевые значения — **0.014–0.019** (§2.1.3), это плотный туман.

### Шаг 4. Отражения — выбери свой случай

**Сначала ответь на три вопроса:**

1. Отражённый мир — это **та же геометрия**, отражённая плоскостью? → **случай А**
2. Или ниже плоскости **реально есть мир** (отдельная копия/измерение/инстанс)? → **случай Б**
3. Или нужно только «мокрый камень и лужи» без чёткого отражения? → **случай В**

| Случай | Что делать | Стоимость |
|---|---|---|
| **А. Плоскость-зеркало** | `FX.registerMirror(new MirrorPlane(y, roughness, true))` при загрузке мира | ~1.2 мс (Tier B) |
| **Б. Зеркальный мир как геометрия** | ничего не регистрировать; пол — **прозрачный блок** с материалом поглощения; поставить `"allowInMirrorWorldMode": true` | **0 мс** ⭐ |
| **В. Только SSR** | `ssrEnabled = true`, ближние 24 блока; для луж/льда/мокрого камня | ~0.4 мс |

```java
// Случай А — регистрация плоскости
@SubscribeEvent
static void onLevelLoad(LevelEvent.Load e) {
    if (e.getLevel().dimension().equals(HostDimensions.MIRROR)) {
        HostEffects.FX.registerMirror(new MirrorPlane(
            /* planeY */ 4.0,
            /* roughness */ 0.02f,
            /* enableSSR */ true
        ));
    }
}
```

> **Рекомендация.** Если структура хоста позволяет случай Б — используй его.
> Он даёт идеальное отражение **бесплатно** (отражённый мир рисуется как обычная
> геометрия), работает на любом железе и не страдает от задержки обновления.
> Случай А — когда нижнего мира физически не существует.

**Проверка шага 4 (только для А):** объект над полом виден в отражении; яркость
отражения ≈ **0.74** от объекта (§7.1); геометрия ниже плоскости в отражении
**отсутствует**; при движении камеры отражение не «дёргается».

### Шаг 5. Свет

**Вариант «ничего не делать»** (рекомендуется по умолчанию):

```toml
[general]
autoScanEmissive = true
```

Модуль сам раз в секунду сканирует область вокруг игрока 64×64×48, находит блоки с
`getLightEmission() ≥ 10`, сливает близкие в один источник и создаёт объёмные ореолы.
Именно это даёт в кадре **красные ореолы вокруг фонарей** из референса без единой
строки кода.

**Точная настройка** — `config/volfx/blocks.json`:

```json
{
  "hostmod:red_lantern": { "color": [1.0, 0.16, 0.18], "intensity": 2.2, "radius": 12.0, "volumetric": true },
  "hostmod:glow_crystal": { "color": [0.55, 0.8, 1.0], "intensity": 3.0, "radius": 18.0, "volumetric": true },
  "minecraft:torch":      { "color": [1.0, 0.62, 0.25], "intensity": 0.7, "radius": 6.0,  "volumetric": true },
  "minecraft:lava":       { "color": [1.0, 0.42, 0.12], "intensity": 1.6, "radius": 10.0, "volumetric": true }
}
```

**Динамические источники** (подвижные сущности, кристаллы, механизмы):

```java
LightHandle h = FX.addLight(new PointLight(pos, color, intensity, radius, true));
// при удалении сущности — ОБЯЗАТЕЛЬНО:
FX.remove(h);        // иначе утечка списка источников и просадка
```

**Проверка шага 5:** вокруг фонаря в тумане появляется объёмный ореол;
цвет ядра после тонмаппинга попадает в диапазон **`#984A4A…#B96B6D`** (§2.1.6);
затухание с расстоянием видно на 3–6 блоках.

### Шаг 7. Небо и «глаз»

Если «глаз» в хосте — **отдельная текстура скайбокса**, самый простой путь: вынести его
в слой неба, чтобы он корректно тонул в тумане.


**Обязательные требования к слою «глаза»** (§10.2): мягкие края (градиент ≥ 25 px на
1080p), параллакс обязателен (иначе «приклеен к экрану»), контраст над небом **+34 ± 10**
единиц яркости, гаснет в тумане **раньше** структур.

**Проверка шага 7:** при движении камеры «глаз» смещается относительно дальних
структур (параллакс есть); при погружении в туман исчезает первым.

### Шаг 8. Постобработка и грейд


**Проверка шага 8:** в кадре **нет полос** на плавных градиентах неба и тумана
(гейт G8: 0 ступеней ≥ 2/255); средняя насыщенность кадра **0.09–0.13**.

## 13.7. ПРАВИЛА РАБОТЫ (контракт ИИ-агента)

### Что делать

1. **Соблюдать порядок §13.5.** После каждого шага — проверка. Не переходить дальше
   при непройденной проверке.
2. **Сначала минимальная версия (§19.1)**, потом полная. Она даёт ~70% картинки за

3. **Все числа брать из §2.** Любое значение в коде (цвет, плотность, коэффициент,

4. **Сверять картинку с референсами по метрикам.** Скриншот + `/volfx debug metrics` +
   таблица «измерено / эталон / допуск». «Похоже» не является результатом.
5. **Держать бюджет (§15.1).** Замерять `GL_TIME_ELAPSED` по пассам, а не «на глаз».
6. **Проверять себя на программном растеризаторе** (нет compute, нет 3D-текстур).
7. **Идти от простого к сложному только вверх:** сначала туман, потом свет, потом
   отражения, потом пар.
8. **Сообщать о неопределённости** в отчёте (§24), а не «додумывать» молча.

### Что НЕ делать (жёсткие запреты)

## 13.8. ДИАГНОСТИКА: СИМПТОМ → ПРИЧИНА → РЕШЕНИЕ

| Симптом | Вероятная причина | Решение |
|---|---|---|
| Чёрный экран | Активный FBO разбиндился после копирования глубины | После `copyDepthFrom` — ручная привязка таргета (§14, грабля 2) |
| Туман не виден вообще | `sigma0` слишком мал; или профиль не привязан к измерению; или ванильный туман не отменён и перекрывает | `sigma0` → 0.014–0.019; проверить `setAtmosphere`; отменить `RenderFog` |
| Видна горизонтальная полоса на месте горизонта | Аналитический хвост не работает или обрезан по `renderDistance` | Включить `farTailMode: "analytic_saturating"` (§5.5) |
| Туман «прилипает» к камере, искажается | Глубина взята в нелинейном виде | Линеаризовать глубину перед реконструкцией мира |
| Полосы на небе и в тумане | Нет дизеринга; или промежуточный таргет 8-бит | Включить blue-noise дизеринг; все таргеты — 16F (§3.3) |
| Отражение «дёргается» при ходьбе | Обновление с задержкой без репроекции | Включить репроекцию по движению камеры (§7.1) |
| В отражении видна изнанка мира | Нет косого отсечения near-плоскости | Матрица отсечения по Ленгелю (§7.1) |
| Пар режется жёсткой кромкой об пол | Нет soft particles или копия глубины сделана **после** прозрачных | Копия глубины до прозрачных; `softDistance = 1.5` (§8.3) |
| Пар выглядит «поверх» тумана | Туман не применён к прозрачным фрагментам | Применять туман к каждому прозрачному фрагменту (§3.2) |
| Ореолы фонарей плоские/квадратные | Затухание `1/r` вместо `1/r²`; отсечка по радиусу без сглаживания | `1/r²` + мягкая граница радиуса (§6.2) |
| «Глаз» приклеен к экрану | Нет параллакса слоя | Задать `parallax` (§10.2) |
| «Глаз» исчез в тумане раньше времени / виден всегда | Тип слоя или порядок пасса неверны | Слои рисуются **до** композита тумана (§10.1) |
| Резкий скачок картинки при удалении | Нет кросс-фейда между LOD | Плавный переход 15–25 м (§15.3) |
| Провал FPS после включения | Нет отсечений или фроксели считаются при нулевой плотности | Ранний выход при `d < 1e-4` (§5.4) + `QualityLadder` (§15.2) |
| FPS падает при плотном тумане | Не реализовано отсечение по видимости | Пороги видимости 64/32/8 м (§15.7) |
| Краш на Fabulous Graphics | Не учтена цель `particlesTarget` | Проверка `useShaderTransparency()` в каждом пассе (§14, грабля 3) |
| Краш на CI/софтверном рендере | Compute или 3D-текстуры сделаны обязательными | Compute — только опция с откатом на атлас (§5.3) |
| VRAM растёт после `/volfx reload` | Утечка FBO/текстур при перезагрузке | Освобождать ресурсы в reload-listener (§14, грабля 12) |
| Мод не грузится без модуля | Зависимость объявлена `mandatory=true` | `mandatory=false` + `VolFxFactory.get()` → `NoopVolFx` |
| Двойной туман | Другой мод тоже правит туман | Приоритет по конфигу + детект известных конфликтов (§20, риск 7) |

## 13.9. Расширение API (если хосту нужно больше)

Точки расширения, зарезервированные на будущее — **без изменения существующих сигнатур**
(правило обратной совместимости: новые методы добавляются в конец интерфейса, старые
не меняются):

| Расширение | Назначение | Интерфейс |
|---|---|---|
| Полноценная симуляция пара со столкновениями | Лавовые потоки, дымовые трубы, взаимодействие с блоками | `ISteamSolver` (реализуется отдельным модулем, подключается через `VolFx.attachSolver(...)`) |
| Кастомные фазовые функции / среды | Пыль, пепел, песчаная взвесь | `IMedium` в профиле |
| Дополнительные объёмные поля | Магическая энергия, аномалии | `VolumeFieldHandle` |
| Кастомный пост-эффект | Специфичные для хоста эффекты | `IPostEffect` в цепочке §11.1 |
| Экспорт карты видимости | Механики на основе тумана | `visibilityAt()` уже есть; расширение — 3D-сетка значений |

**Правило для агента:** если хост требует функциональность, которой нет — **не
расширять API самовольно**. Зафиксировать потребность в отчёте (§24, раздел

# 14. РЕАЛИЗАЦИЯ В MINECRAFT 1.20.1 — ГРАБЛИ И РЕШЕНИЯ

| # | Грабля рендера Minecraft 1.20.1 | Решение в модуле |
|---|---|---|
| 1 | `ShaderInstance.apply()` связывает **только `GL_TEXTURE_2D`** — `sampler3D`/`imageStore` недоступны | **Фроксельный атлас** (§5.3) — всё 2D. 3D-текстуры не нужны вообще |
| 2 | `RenderTarget.copyDepthFrom(...)` **разбиндивает FBO (→0)** | После каждого вызова — ручная привязка `GlStateManager._glBindFramebuffer(GL_FRAMEBUFFER, mainTarget.frameBufferId)` |
| 3 | Fabulous-графика: активна цель `particlesTarget`, `Minecraft.useShaderTransparency()` | Все пассы проверяют `useShaderTransparency()` и работают с корректной целью; **обязательный GameTest** (`noCrashWithFabulous`) |
| 4 | Ванильные частицы: `depthMask(true)`, discard `alpha < 0.1` | Пар рисуется **своим пассом** (не `ParticleRenderType`): `depthMask(false)` |
| 5 | **Главный таргет — 8 бит** (HDR в сцене нет) | Копия в `hdrScene` (RGBA16F) перед постом; HDR-энергию дают **только наши эффекты** (туман-инскоттер, bloom-источники). Ограничение зафиксировано в §20 |
| 6 | В главном таргете нет stencil | Зеркальный проход использует **свой FBO** с `DEPTH24_STENCIL8`; на stencil главного таргета не полагаться |
| 7 | `levelRenderer.renderLevel(...)` рекурсивен | `boolean guard` + запрет рекурсии в отражение; зеркал в зеркалах **нет** (max depth = 1) |
| 8 | `ViewportEvent.RenderFog` отменяет ванильный туман, но **не даёт мировой Y** | Вариант A (§5.7): ванильный туман выключаем, свой — по `depthCopy` |
| 9 | GL 3.2 Core: нет compute, нет SSBO, нет `imageStore` | Компьют — **только опциональная ветка** (§5.3). CI-прогон обязателен **без** него (llvmpipe) |
| 10 | `glTexSubImage2D` + атласы: строки текут между тайлами | `GL_UNPACK_ROW_LENGTH` для вложенных апдейтов; при сэмплировании — clamp на полтексела внутрь тайла |
| 11 | Размер фреймбуфера ≠ размер окна (GUI-scale) | Все пассы используют `mc.getWindow().getWidth()/getHeight()` (framebuffer); UI-масштаб не применяется к эффектам |
| 12 | Ресурсы перезагружаются (F3+T, смена пака) | Всё создаётся в `RegisterClientReloadListenersEvent`; обязательная корректная очистка (иначе утечка VRAM) |
| 13 | `GlStateManager` не сохраняет всё автоматически | Каждый эффект-пасс оборачивается в `pushState/popState` с полным набором: blend, depthMask, cullFace, program, VAO, activeTexture |
| 14 | Тени/lightmap: непрозрачная геометрия ниже зеркала | Косое near-плоскость (Lengyel) в отражении |
| 15 | Производительность Xvfb/llvmpipe: 5–20 FPS | Гейты используют **таймаут ожидания кадра**, а не «N кадров за T секунд»; бюджет-тесты на llvmpipe помечены как «sanity, не perf» |
| 16 | Прямая запись в `LightTexture`/lightmap | `volfx` **не пишет** в lightmap (это ломает чанки). Затемнение под туманом делается эффектами |

## 15.2. Лестница качества (`QualityLadder`)

```
0. OFF       — модуль выключен (эффектов нет, как сейчас)
1. MINIMAL   — только туман (фроксели 1/2, 32 слайса, 8 шагов композита), без отражений/света
2. LOW       — туман + аналитический хвост + дизеринг, тени хайтфилда выкл.
3. MEDIUM    — + солнце + точечные источники, отражение 1/4 (10 Гц), bloom
4. HIGH      ← ДЕФОЛТ: всё из §5–§11, фроксели 160×120×48, отражение 1/2 (20 Гц), 3 октавы
5. ULTRA     — фроксели 240×135×64, отражение 3/4 (каждый кадр), 5 октав, DOF, motion blur
6. CINEMATIC — без бюджета (для скриншотов/видео), отключает деградацию
```

**Автоматика:**
- 3 кадра подряд хуже бюджета → ступень вниз (не более 1 за раз);
- 30 с стабильности → ступень вверх (гистерезис, апгрейд медленнее);
- **никогда** не понижать во время скриншот-сессии (флаг `cinematic`);
- понижение **никогда** не отключает дизеринг и дизеринг-подобные фиксы качества (иначе «дёшево» выглядит хуже, чем «пусто»).

## 15.3. Отсечения (в порядке применения)

```
1. Frustum cull        — AABB источников света и эмиттеров
2. Distance cull       — отражение: только для зеркал в радиусе 96 м
3. Плотностный ранний выход — 70% фрокселей пусты → не считаем свет (§5.4)
4. Слайсовая отсечка света — 8× ускорение (§6.2)
5. Early-out композита — T < 0.004 (§5.5)
6. Отсечение по видимости — при видимости < 32 м не рисуем дальние слои (§15.7)
7. Зеркало не обновляется — если камера не движется и сцена статична (проверка хеша позиций источников + камеры), пропускаем P5 целиком
8. Отключение пар-пасса — если эмиттеров нет в фрустуме
```

## 15.4. Temporal-стратегии

| Что | Стратегия |
|---|---|
| Композит тумана | Джиттер + репроекция по движению камеры (1/2 вычислительных шагов) |
| Отражение | Обновление 20 Гц + репроекция при использовании (иначе «дёргается») |
| Отражение (Tier C) | Обновление 10 Гц + усиленное размытие по шероховатости (маскирует задержку) |
| Фроксель-генерация | Обновление каждый 2-й кадр при статичной камере (Tier C) |
| Пар | Нет (stateless, детерминирован) |

**Требование к репроекции:** обязательный **clamp по соседям** (neighborhood clamping) — иначе ghosting на движущихся объектах. На референсных кадрах ghosting недопустим (это «мыло» на статичных силуэтах).

## 15.5. Память и аллокации

- **Ноль аллокаций в кадре.** Проверяется тестом: 600 кадров, ни одной полной GC, ≤ 2 молодых.
- Пул объектов: `FroxelSample`, `LightRef`, `Vec3` — `ThreadLocal`/`ArrayDeque`.
- Прямые `FloatBuffer` для всех загрузок; никаких промежуточных `float[]` в кадре.
- FBO/VBO/текстуры **создаются один раз** и переиспользуются. Никаких `new RenderTarget` в кадре (типичная утечка).

## 15.6. Асинхронность

- Heightfield-тени (§6.5) — **отдельный поток**, публикация снапшота в главный поток (double-buffer).
- Сканирование эмиссивных блоков — **отдельный поток** (или главный, но не чаще 1 Гц и не более 256 блоков/тик).
- Загрузка профилей/LUT — **асинхронная**, с аварийным «оставить предыдущее» при ошибке.
- **Ни один GL-вызов — не из фонового потока.** Только `StagingRingBuffer` (2–3 слота) + `glFenceSync`/`glClientWaitSync` с нулевым таймаутом (не блокировать рендер никогда).

## 15.7. «Туман бесплатен, когда ничего не видно» (обязательный приём)

```
visibility = 1/σ_t  (метры)

if (visibility < 64)  → LOD дальней сцены отключается, отражение 1/4, 16 шагов композита
if (visibility < 32)  → отражение выключается, туман 12 шагов, пар-пасс только ближний
if (visibility < 8)   → whiteout: рендерим только 16 м вокруг, остальное — чистый цвет тумана
```

Это самая выгодная оптимизация из возможных: **чем хуже видно, тем дешевле кадр**. На референсах `visibility ≈ 50–160 м`, то есть штатный режим уже экономит ~40%.

## 15.8. Профилировщик (в модуле)

- `/volfx debug hud` — оверлей: время по пассам, число активных источников/эмиттеров, `τ` в центре экрана, текущая ступень качества, VRAM.
- `/volfx debug profile 120` — CSV по кадрам.
- `/volfx debug freeze` — фиксирует время и джиттер (для скриншот-гейтов — **обязательно**, иначе кадры не воспроизводимы).
- `/volfx debug profile <name>` — мгновенная смена арт-профиля.

# 22. ГЛОССАРИЙ

| Термин | Значение |
|---|---|
| **Фроксель** | Элемент экранно-выровненной 3D-сетки (XY = тайл экрана, Z = слайс вдоль луча). Единица вычисления объёмного тумана |
| **Фроксельный атлас** | Укладка 3D-объёма в 2D-текстуру тайлами. Позволяет работать без 3D-текстур и compute (GL 3.2) |
| **In-scattering** | Свет, рассеянный средой **в** направлении наблюдателя. Именно он делает небо и туман «светящимися» |
| **Оптическая толща (τ)** | Безразмерная мера мутности вдоль луча: `∫σ_t ds`. `τ = 1` → 63% ослабление, `τ = 3` → 95% |
| **Трансмиттанс (T)** | Доля света, прошедшая среду: `T = exp(-τ)` |
| **Аналитический хвост** | Закрытая формула интеграла тумана за пределами фроксельной сетки. Даёт «стену тумана» на горизонте |
| **HG (Henyey–Greenstein)** | Фазовая функция рассеяния, параметр `g` = анизотропия (0 = изотропно, →1 = сильно вперёд) |
| **Многократное рассеяние** | Свет, рассеявшийся более одного раза. Аппроксимируется октавами (Wrenninge/Hillaire) |
| **ACES** | Киношный тонмаппинг-оператор; даёт «выцветание в белое» без клиппинга |
| **LUT** | Таблица предвычисленных значений (атмосфера — 2D/3D таблицы; грейд — 3D 32³) |
| **Косое отсечение (Lengyel)** | Модификация матрицы проекции так, что near-плоскость совпадает с плоскостью отражения |
| **SSR** | Screen-Space Reflections — отражения по буферу глубины в экранном пространстве |
| **Soft particles** | Растворение частиц у пересечения с геометрией по копии глубины |
| **Stateless particles** | Частицы, положение которых — чистая функция `(индекс, время)`, без симуляции и состояния |
| **Split toning** | Раздельное тонирование светов и теней (здесь: тёплые света / холодные тени) |
| **Бандинг** | Полосы на плавных градиентах из-за 8-битного вывода. Лечится дизерингом |
| **Дизеринг** | Внесение малого шума (1 LSB) перед квантованием, разрушающего полосы |
| **Мировой сид** | Источник детерминированной случайности из мира; обязателен для воспроизводимости кадров |

# 23. ЗАКЛЮЧИТЕЛЬНЫЕ ТРЕБОВАНИЯ

1. **Хост-мод не переписывается.** Только 3 обязательных вызова + опциональные регистрации через API.
2. **Один центральный механизм — фроксельный туман.** Он даёт туман, высоту, свет, лучи, порядок прозрачности, корректность отражений и частиц. Не дублировать логику в каждом эффекте.
3. **Небо не рисуется текстурой.** Только интеграл рассеяния + слои.
4. **Никаких жёстких границ** — ни по дистанции, ни по высоте, ни по LOD, ни по качеству.
5. **Дизеринг обязателен и не отключается** обычным конфигом.
6. **GL 3.2 Core без compute — базовый путь.** Compute — только ускорение с гарантированным откатом.
7. **Все параметры — в JSON-профилях.** Ни одного «магического числа» в коде без ссылки на §2/§5.
8. **Горячая перезагрузка обязательна** — иначе итерации по картинке невозможны.
9. **Каждый гейт — с числом и допуском.** «Похоже» не является критерием приёмки.
10. **Компромиссы из §20 не скрывать** в отчёте.
