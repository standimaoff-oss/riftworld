## 2. Движок: что именно изменилось в силуэте

Старый генератор ставил «шары листвы» на палку — отсюда и «ужасные» биомы. Новый движок (1:1 в Java и Python):

1. **Ствол — конус с наклоном и лёгким изгибом.** Радиус у земли больше и медленно убывает
   (`base·(1 − 0.52·t) + 0.08`), поэтому у сизо-гиганта настоящий ствол 2×2, а у лилового древа — заметный комель.
   Раньше наклон/«змея» были ±0.9 блока — дерево изгибалось как лиана; теперь ±0.45.
2. **Ветви — настоящие брёвна.** Из ствола в 3–4 ярусах выходят ветви (ось `X`/`Z` выставляется по направлению),
   у 55 % ветвей есть развилка. Длина ветви ~0.7–1.0 радиуса кроны, подъём 0.5–0.85 блока на блок.
3. **Крона — объединение листовых облаков** (`blob()`), по одному на кончик ветви, а не «блин» на ярус.
   Облако рваное: 40 % пропусков по кромке (`q > 0.45`), 30 % мелких дырок в середине (`q < 0.22`),
   акцентные блоки только по кромке. Верхушку венчает облако-лидер.
4. **Свисающая юбка и лианы** под кромкой кроны, у лилового древа — акцентные цветочные блоки (20 % по кромке).
5. **Конифер** (туманная сосна) — ярусы-кольца, сужающиеся к вершине, **папоротник** — вайи, поднимающиеся
   из кроны и провисающие на концах.
6. Всё детерминировано от `(kind, height, seed)` — мир не «мерцает» при перегенерации.

## 4. Аддон к Dynamic Trees — `dtcompat/`

Требование ТЗ: **настоящий аддон**, 4 породы. Сделан как **data-only мод**: в нём нет ни одного Java-класса,
только дерево-пак, который Dynamic Trees 1.20.1 подхватывает из `trees/<pack>/` любого мода
(`ModTreeResourcePack` → `trees`-папка; имена паков = имена каталогов). Это осознанное решение:

- **не зависит от API DT** — не сломается при смене внутренностей и собирается без jar DT в classpath;
- **soft-dependency**: у каждой family/species/soil стоит `only_if_loaded: "dynamictrees"`, у мода в `mods.toml`
  DT помечен `optional` — без DT мод грузится пустым и ничего не ломает;
- всё остальное — обычный Forge-проект (`dtcompat/build.gradle`, `gradlew` можно взять из `mod/`).

Содержимое (`python3 tools/rift/gen_dt_addon.py` — идемпотентно пересобирает всё):

| species | порода | биом | cell kit | growth logic | tapering / energy / rate |
|---|---|---|---|---|---|
| `riftworld_dt:lilac` | сиреневое древо | `riftworld:violet_hills` | deciduous | — | 0.34 / 16 / 0.72 |
| `riftworld_dt:sizo_v2` | сизо v2 (толстое) | `riftworld:sizo_grove` | deciduous | dark_oak | 0.28 / 20 / 0.62 |
| `riftworld_dt:fern_tree` | древовидный папоротник | `riftworld:waterfall_gardens` | palm | palm | 0.55 / 8 / 1.15 |
| `riftworld_dt:mist_pine` | туманная сосна | `riftworld:mist_keep` | conifer | conifer | 0.42 / 13 / 0.66 |

Дополнительно:

- `families/*.json` с `primitive_log: riftworld:<порода>_log` и `texture_overrides` (кора и спил берутся
  из **наших** текстур, так что ветви выглядят как стволы);
- `leaves_properties/*.json` с `primitive_leaves: riftworld:<порода>_leaves`;
- `soil_properties/{elisar_grass,elisar_soil,elisar_moss}.json` — DT умеет расти **на наших блоках земли**
  (иначе деревья не появятся ни в мире, ни из семян);
- `world_gen/riftworld.json` — density/chance по биомам, в `ashen_lands` и `elisar_city` прописан `species: "null"`;
- семена: 4 спрайта 16×16 (`assets/riftworld_dt/textures/item/*_seed.png`), модели, lang ru/en.

**Что важно понимать:** мод при этом **не удаляет** собственные деревья мода. В игре, если DT установлен,
оба набора сосуществуют (DT растит свои, движок мода — свои). Если нужен режим «только DT», это одна строка
в `ElisarChunkGenerator.treesChunk()` — выключаем вызов по флагу конфига; скажи, и сделаю.

## 5. Проверка (и честное ограничение)

Требование «установить всё, собрать, запустить игру и приложить фото» **в этой песочнице невыполнимо**:
нет `java/javac/gradle`, а Minecraft/Forge/Mojang/Maven недоступны по сети (проверено curl'ом: HTTP 000).
Поэтому проверка сделана тем, что реально доступно:

1. **Синтаксис Java** — tree-sitter-java по всем 108 файлам: **0 ошибок**. (`javalang` не годится: не понимает
   records и switch-expression, давал 45 ложных ошибок.)
2. **Ресурсы — `python3 tools/rift/validate_assets.py`**: парсит реестр блоков из Java и проверяет у каждого блока
   blockstate → модели → текстуры → item-модель → лут → переводы ru/en, плюс аддон DT (ссылки на блоки мода,
   спрайты семян, `mods.toml`, `pack.mcmeta`).
   Итог: **139 блоков, 0 проблем в новых блоках**; 12 унаследованных замечаний (arena_core, boss_column и т. п. —
   не мои блоки, было до Рев 7, показываются флагом `-v`).
3. **Все 1256 JSON ресурсов парсятся**, `mods.toml` аддона валиден как TOML.
4. **Сверка движков**: `tools/rift/tree_gen.py` (эталон) и `TreeGen.java` — сверены `SPECS` (7 пород, все числа
   совпадают) и контрольные вызовы; отрисовка сцен идёт **тем же** Python-эталоном.
5. **Фото-рендеры** (`tools/rift/mock_world.py`, ~4 с на прогон): настоящие текстуры мода, AO, крест-накрест

## 7. Как собрать и запустить (у себя, где есть интернет)

```bash
# 1) основной мод
cd mod && ./gradlew build          # -> mod/build/libs/riftworld-0.6.1.jar

# 2) аддон к Dynamic Trees (необязателен, но именно он делает деревья «DT-шными»)
cd ../dtcompat && python3 ../tools/rift/gen_dt_addon.py && ./gradlew build
#    -> dtcompat/build/libs/riftworld_dt-1.0.0.jar

# 3) в игру: Forge 1.20.1-47.4.23 + Dynamic Trees 1.20.1 + оба jar, мир с генератором riftworld:elisar
```

Запуск из IDE: `cd mod && ./gradlew runClient`; для аддона с DT — положить jar DT в `dtcompat/libs/`
(в `build.gradle` он подхватывается как `runtimeOnly`, если лежит в `libs/`).
