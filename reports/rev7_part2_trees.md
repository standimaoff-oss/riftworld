## 2. Главное изменение: деревья строит Dynamic Trees

Раньше мод ставил свои деревья всегда. Теперь наоборот:

```java
// ElisarChunkGenerator, конец чанка
if (DynamicTreesCompat.ownTreesEnabled()) treesChunk(plan, chunk, mp, x0, z0);
mistKeepDressing(plan, chunk, mp, x0, z0);       // декоративная мелочь — всегда
```

`DynamicTreesCompat` не ссылается ни на один класс DT (только `ModList.get().isLoaded("dynamictrees")`),
поэтому мод по-прежнему собирается и работает без DT, а ответ кэшируется — генератор чанков не дёргает мод-листу
на каждый чанк. Решение «кто владеет деревьями» принимается **в одном месте**, чтобы в мире не выросли два дерева
в одной точке.

Если DT не установлен — работает прежний встроенный движок (см. §3), и биомы выглядят как раньше.

## 3. Фолбэк-движок (когда DT нет)

1. **Ствол — конус с наклоном и комлем**, радиус у земли больше (`base·(1 − 0.52·t) + 0.08`).
2. **Ветви — настоящие брёвна** с осью по направлению, у 55 % есть развилка.
3. **Крона — объединение рваных листовых облаков** на кончиках ветвей (40 % пропусков по кромке, 30 % дырок
   в середине), а не «блин» на ярус.
4. **Свисающая юбка и лианы**, у лилового древа — акцентное цветение (20 % по кромке).
5. **Конифер** — ярусы-кольца к вершине, **папоротник** — вайи.
6. Всё детерминировано от `(kind, height, seed)`.

Паритет Java ↔ Python проверяется на каждом прогоне: **144 дерева, 61 952 строки совпали байт в байт**.
Именно поэтому офлайн-рендеры (снятые Python-эталоном) честно показывают то, что поставит Java.

## 4. Аддон к Dynamic Trees — `dtcompat/`

**Data-only мод**: ни одного Java-класса, только дерево-пак, который DT 1.20.1 подхватывает из `trees/<pack>/`
любого мода. Плюс: не зависит от внутреннего API DT и собирается без его jar в classpath.

4 породы — ровно столько, сколько просил пользователь:

| species | порода | биом | cell kit | growth logic | tapering / energy / rate / up / ветки с / радиус |
|---|---|---|---|---|---|
| `riftworld_dt:lilac` | сиреневое древо | `riftworld:violet_hills` | deciduous | — | 0.34 / 16 / 0.72 / 3 / 5 / 7 |
| `riftworld_dt:sizo_v2` | сизо (толстое, 2-е поколение) | `riftworld:sizo_grove` | **dark_oak** | dark_oak | 0.26 / 24 / 0.60 / 5 / 9 / 12 |
| `riftworld_dt:fern_tree` | древовидный папоротник | `riftworld:waterfall_gardens` | palm | palm | 0.55 / 7 / 1.15 / 1 / 2 / 5 |
| `riftworld_dt:mist_pine` | туманная сосна | `riftworld:mist_keep` | conifer | conifer | 0.42 / 14 / 0.66 / 4 / 3 / 6 |

Что ещё в паке:

- `families/*.json` — `primitive_log: riftworld:<порода>_log`, свои `texture_overrides` (кора и спил берутся из
  **наших** текстур, поэтому ветви выглядят как ствол), `primary/secondary_thickness`, `loot_volume_multiplier`;
- `leaves_properties/*.json` — `primitive_leaves: riftworld:<порода>_leaves`, `cell_kit`, горючесть/распространение
  огня, `light_requirement`, `requires_shears`;
- `soil_properties/{elisar_grass,elisar_soil,elisar_moss}.json` — DT растёт **на наших блоках земли** (иначе ни
  мировых деревьев, ни посадки из семян);
- `world_gen/riftworld.json` — по записи на биом, `density: [1.0]`, `chance: 1.0` (совет самого DT для аддонов),
  в `ashen_lands` и `elisar_city` — `species: "null"`; биомы мода вообще не содержат ванильных tree-фич, так что
  второго источника деревьев в них нет;
- семена: `generate_seed: true` + спрайты 16×16, модели и переводы ru/en. `generate_sapling: false` — модели
  саженца у нас нет, а обещать предмет без модели нельзя (семена DT роняет сама, посадить можно).

Аддон проверен против **Dynamic Trees 1.4.11** (ветка `release/1.20.1`, из неё же собрана схема); в `mods.toml`
диапазон `[1.4,)`, версия мода в зависимостях — из `mod/gradle.properties`.

**Мягкая зависимость:** у каждой family/species/soil стоит `only_if_loaded: "dynamictrees"`, в `mods.toml` DT
помечен `optional`. Без DT пак просто ничего не делает.

### Почему ключи именно такие

`tools/rift/dt_schema.json` — не выдумка и не копипаста из вики. Он собирается `tools/rift/fetch_dt_schema.py`
из двух независимых источников Dynamic Trees `release/1.20.1`:

1. **код лоадеров** (`SpeciesResourceLoader`, `FamilyResourceLoader`, `LeavesPropertiesResourceLoader`,
   `SoilPropertiesResourceLoader`) — какие ключи и **каких Java-типов** регистрируются;
2. **собственный пак DT** (`src/main/resources/trees/dynamictrees/…`, 77 файлов) — какие ключи DT реально
   использует.

Второй источник оказался не лишним: `family` в species **не** регистрируется в лоадере (его разбирает реестровый
загрузчик), и «схема по regex» его бы запретила, хотя DT сам пишет `"family": "dark_oak"` в своём паке.
Именно так в первой версии пака в species попали ключи уровня family (`primary_thickness`, `secondary_thickness`,
`loot_volume_multiplier`) — DT бы их молча проигнорировал; теперь они только в family, где и работают.

Схема (итог): species **60** ключей, family **28**, leaves **25**, soil **12**; `cell_kits` 8, `growth_logic_kits` 7,
типы почв 12. Для каждого числового ключа хранится и **диапазон значений из пака DT** — по нему валидатор ловит
опечатки вроде `tapering: 3.4`.

### Что эти проверки уже поймали в этой итерации

- **`versionRange = "[1.0,)"` у зависимости от мода** при версии мода 0.6.1 — Forge не загрузил бы аддон вообще
  (обязательная зависимость не выполнена). Теперь версии берутся из `gradle.properties`, а валидатор сверяет, что
  версия мода попадает в диапазон, и что версия в `mods.toml` совпадает с `dt_addon_version`.
- **ключи уровня family в species** (`primary_thickness`, `secondary_thickness`, `loot_volume_multiplier`) — DT их
  молча игнорирует.
- **недетерминированные спрайты семян**: `random.Random(hash(name))` в Python солится каждым процессом, поэтому
  каждый прогон генератора делал другие PNG. Заменено на `zlib.crc32`; проверено двумя прогонами подряд.
- **`family` в species считался нелегальным ключом** — это была ошибка не пака, а моей первой схемы: она строилась
  только по regex лоадеров. Отсюда требование к `fetch_dt_schema.py` брать ещё и собственный пак DT.

Два предупреждения валидатора — осознанные и закомментированы в `gen_dt_addon.py`: у `fern_tree` и `mist_pine`
`tapering` (0.55 и 0.42) выше верхней границы пака DT (0.40). Это сделано ради тонких, «кривых» силуэтов; всё
остальное лежит внутри диапазонов самого DT, чтобы странное дерево всегда объяснялось замыслом, а не опечаткой.

Чего эти проверки **не** заменяют: загрузку пака живым DT (он логирует ошибки десериализации в `latest.log`) и
вид дерева, выросшего по этим параметрам. Ни то, ни другое офлайн не воспроизводится — форму дерева в DT
определяет его собственный солвер роста, а не наш код.

## 7. Как собрать и запустить (у себя, где есть интернет)

```bash
# 1) основной мод
cd mod && ./gradlew build          # -> mod/build/libs/riftworld-*.jar

# 2) аддон к Dynamic Trees
cd ../dtcompat && python3 ../tools/rift/gen_dt_addon.py && ./gradlew build
#    -> dtcompat/build/libs/riftworld_dt-1.0.0.jar

# 3) в игру: Forge 1.20.1-47.4.23 + Dynamic Trees 1.20.1 + оба jar, мир с генератором riftworld:elisar
#    без DT тоже работает: деревья вырастит встроенный движок
```

Проверка после запуска (то, что офлайн не проверяется):

1. `latest.log` — нет строк `Could not load species` / `Could not set common species` и подобных;
2. в биомах 04/05/07/данж растут **DT-деревья** (толстый ствол, ветви, листва по kit'у), а не «палки»;
3. `F3` — в биоме 04 вид `riftworld:violet_hills`, деревья дропают семена мода.

## 8. Осталось / на твоё решение

1. **Прогон в игре** — единственное, что закрывает вопрос «как это выглядит с DT». Нужен твой скриншот или лог.
2. **Параметры силуэта** — сейчас подобраны расчётом и по диапазонам DT; после первого живого взгляда их стоит
   подкрутить (например, `signal_energy` у сизо 24 — он самый высокий из четырёх).
3. **Саженцы** — сознательно не включены (нет модели). Если нужны — сделаю модель `sapling` и включу
   `generate_sapling`.
